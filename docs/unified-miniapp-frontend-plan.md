# 统一平台小程序制作方案（简洁版前端）

更新时间：2026-09-14  
适用模式：一个平台小程序、多家商户共用；腾讯地图门店页携带门店入口参数，直接打开对应商家。

## 1. 产品目标

第一版只解决一件事：顾客从腾讯地图或微信位置进入后，能快速看懂门店和套餐，完成付款、预约、查看券码。

核心原则：

- 一个页面只保留一个主要操作。
- 地图进入后直接显示对应门店，不让顾客再次搜索。
- 第一版不做购物车，每次只购买一项服务、数量固定为 1。
- 价格、有效期、预约要求、补差和退款规则在付款前明确展示。
- 支付商户号只能由服务器根据门店决定，前端不能选择或传入。
- 店员核销放在 SaaS 管理后台，不混入顾客小程序。
- 所有页面必须提供加载、空数据、失败、下架、停业和网络重试状态。

## 2. 第一版信息架构

底部只保留 3 个菜单：

1. `首页`：当前门店和套餐。
2. `订单`：待付款、待使用、已使用、退款/失效。
3. `我的`：手机号、客服、协议和设置。

非底部页面：

- 套餐详情。
- 确认订单。
- 支付结果。
- 选择预约时间。
- 订单详情。
- 券码详情。
- 退款申请。
- 门店不可用/入口失效页。

暂不开发：

- 购物车。
- 积分、会员等级、分销、拼团和直播。
- 复杂推荐流和短视频信息流。
- 多规格组合购买。
- 顾客端核销功能。
- 平台内复杂地图和外卖配送。

## 3. 顾客主流程

```text
腾讯地图门店页
  → 点击“团购/预约”
  → 小程序解析 store_code 或 scene
  → 对应门店首页
  → 套餐详情
  → 确认订单
  → 微信支付
  → 预约时间（需要预约的商品）
  → 查看券码
  → 到店出示
  → 店员在 SaaS 核销
```

目标点击数：

- 从门店首页到调起支付不超过 3 次主要点击。
- 支付成功后进入预约或券码不超过 1 次点击。
- 顾客再次进入时，从“订单”到完整券码不超过 2 次点击。

## 4. 页面方案

### 4.1 启动与入口解析

小程序启动时读取：

- 腾讯地图挂载路径中的 `store_code`；或
- 小程序码/分享卡片中的 `scene`；或
- 普通自然进入时使用最近访问门店。

前端把入口参数发送给服务端解析，服务端返回公开门店信息。前端不得接受 `tenant_id` 或商户号作为可信路由参数。

入口错误时显示独立页面：

```text
门店暂时无法打开
入口可能已失效或门店正在维护

[重新加载]  [联系客服]
```

### 4.2 门店首页

页面只分 4 块：

```text
┌──────────────────────────┐
│ 门店头图                  │
│ 缔丝风尚潮色染烫          │
│ 正常营业 · 09:00-21:00    │
│ 河南省漯河市……            │
│ [导航] [电话] [收藏]       │
├──────────────────────────┤
│ 本店套餐                  │
│ ┌──────────────────────┐ │
│ │ 图片  潮色染发体验     │ │
│ │      ¥99  已售 12     │ │
│ │      [查看套餐]        │ │
│ └──────────────────────┘ │
├──────────────────────────┤
│ 门店环境（最多 6 张）      │
├──────────────────────────┤
│ 服务保障 · 使用须知 · 客服 │
└──────────────────────────┘
```

展示内容：

- 门店头图、名称、营业状态。
- 地址、距离（获得位置授权后才计算）、导航和电话。
- 2～6 个在售套餐。
- 最多 6 张门店环境图。
- 服务保障、客服和真实经营信息。

不展示：后台编号、商户号、POI ID、库存内部版本、审核状态和技术错误。

### 4.3 套餐详情

顺序固定：

1. 封面图。
2. 商品名称。
3. 售价、划线价和已售数量。
4. 套餐包含内容。
5. 是否需要预约、服务时长和适用门店。
6. 使用时间、有效期和不可用日期。
7. 长发、漂色、指定发型师等补差说明。
8. 退款规则。
9. 门店地址与导航。
10. 页面底部固定“立即购买”。

简单线框：

```text
[套餐封面图]

潮色染发体验套餐
¥99  ¥168   已售 12

套餐内容
· 基础染发一次
· 洗护和造型

预约与使用规则
· 需提前 2 小时预约
· 长发/漂色可能补差，付款前咨询
· 购买后 30 天有效

退款说明
未核销且在有效期内按页面规则申请

┌──────────────────────────┐
│ ¥99             [立即购买]│
└──────────────────────────┘
```

### 4.4 确认订单

第一版数量固定为 1，不提供加减按钮。

必须展示：

- 门店名称。
- 套餐名称和数量 1。
- 商品金额、优惠、应付总额。
- 预约要求。
- 退款规则摘要。
- 用户协议/退款规则确认勾选。

底部按钮使用金额表达：`微信支付 ¥99.00`。

点击后流程：

1. 前端只提交商品 ID 和入口门店上下文。
2. 服务端重新读取价格、库存、门店和支付配置。
3. 服务端创建订单并返回支付参数。
4. 前端调用 `wx.requestPayment`。
5. 前端支付成功提示不作为最终到账依据；页面轮询服务器订单状态。

### 4.5 支付结果

支付成功：

```text
✓ 支付成功
订单正在确认

[立即预约]  或  [查看券码]
[查看订单]
```

支付取消：

```text
尚未完成支付
订单将在倒计时结束后关闭

[继续支付]
[返回订单]
```

支付结果未知：

```text
正在确认支付结果
请勿重复付款

[刷新结果]
```

禁止显示“前端调起成功＝已经付款”。只有服务端确认微信支付订单成功后，才显示券码。

### 4.6 预约页

页面仅包含：

- 门店和套餐。
- 可预约日期。
- 可选时段。
- 联系人。
- 脱敏手机号或手工输入手机号。
- 备注（选填）。
- “确认预约”按钮。

第一版无需选择发型师；后续有真实排班数据再增加。不可预约时间由服务器返回，前端不自行计算容量。

预约完成后展示门店、日期、时间、电话和改约规则。

### 4.7 订单列表

顶部使用 4 个筛选项：

- 全部。
- 待付款。
- 待使用。
- 已完成/退款。

订单卡片：

```text
缔丝风尚潮色染烫       待使用
潮色染发体验套餐
预约：9月18日 14:00
实付：¥99.00
[查看券码] [查看详情]
```

不要把微信交易号、内部订单 ID 和商户号显示在列表。详情页可显示顾客可读的订单编号。

### 4.8 券码详情

突出显示：

- 券码或二维码。
- 套餐名称。
- 门店名称。
- 有效期。
- 预约时间。
- 当前状态。

状态文案：

- `待使用`：蓝/绿色。
- `已核销`：灰色，并显示核销时间。
- `退款中`：橙色，二维码停止使用。
- `已退款/已过期`：灰色，不展示可扫描二维码。

核销必须由店员后台完成，小程序端只展示顾客凭证。

### 4.9 我的

第一版只保留：

- 微信头像/昵称（用户授权后展示）。
- 我的订单。
- 常用联系人/手机号。
- 联系客服。
- 用户协议。
- 隐私政策。
- 账号注销/个人信息处理入口。
- 当前版本号。

不放积分、会员、推广员和大量营销入口。

## 5. 视觉规范

整体风格：白底、浅灰背景、大字号、少颜色、少弹窗。

推荐设计变量：

| 用途 | 取值 |
| --- | --- |
| 页面背景 | `#F6F7F9` |
| 卡片背景 | `#FFFFFF` |
| 主文字 | `#171A1F` |
| 次文字 | `#6B7280` |
| 分割线 | `#EAECF0` |
| 主色 | `#1677FF` |
| 成功 | `#16A34A` |
| 警告 | `#F59E0B` |
| 错误 | `#DC2626` |
| 卡片圆角 | `16rpx`～`24rpx` |
| 主按钮高度 | 不低于 `88rpx` |
| 页面左右留白 | `24rpx`～`32rpx` |

文字层级：

- 页面标题：36～40rpx，加粗。
- 商品标题：30～34rpx，中等字重。
- 正文：28～30rpx。
- 辅助文字：24～26rpx。
- 价格：36～44rpx，加粗；货币符号稍小。

规则：

- 同一页面主色按钮最多一个。
- 不使用超过 3 种强调色。
- 不用自动轮播 Banner。
- 不用大段居中文字。
- 重要规则用短句和项目符号，不藏在弹窗中。
- 点击区域不小于 88rpx 高或宽。
- 底部固定按钮避开安全区。

允许每家商户上传 Logo、头图和最多一个品牌主色；按钮颜色必须经过对比度检查，不能由商户自由设置所有页面样式。

## 6. 公共组件

第一版只建立这些组件：

- `StoreHeader`：门店名称、状态、地址、导航和电话。
- `ProductCard`：图片、名称、价格、已售和状态。
- `PriceBlock`：统一金额展示。
- `RuleSection`：使用/预约/退款规则。
- `OrderCard`：订单摘要和状态动作。
- `AppointmentPicker`：日期、时段和不可选状态。
- `VoucherCard`：券码、二维码和有效期。
- `PrimaryBottomBar`：底部金额和主按钮。
- `PageState`：加载、空数据、失败、停业和下架。
- `ConfirmSheet`：仅用于退款、取消预约等高风险确认。

所有页面复用这些组件，避免每个商家做一套不同界面。

## 7. 前端数据与接口改造

当前 `miniapp/config.example.js` 固定后台 `miniProgramId`，需要改成平台级配置：

```js
module.exports = {
  apiBaseUrl: 'https://api.example.com/api/v1'
}
```

门店由入口动态解析，不再写死到安装包。

建议新增/调整接口：

```text
POST /public/platform-mini-program/login
POST /public/store-entry/resolve
GET  /public/stores/{store_code}
GET  /public/stores/{store_code}/products
GET  /public/products/{product_id}
POST /public/orders
GET  /public/orders
GET  /public/orders/{order_id}
POST /public/orders/{order_id}/pay
POST /public/orders/{order_id}/appointment
GET  /public/orders/{order_id}/voucher
POST /public/orders/{order_id}/refunds
GET  /public/refunds/{refund_id}
```

前端请求中允许出现 `store_code/product_id/order_id`；不得出现可决定收款方的 `tenant_id/mchid/sub_mchid`。

## 8. 状态和错误处理

必须处理：

- 门店不存在、停业、欠费停用或入口审核失效。
- 商品下架、售罄、价格变化和库存不足。
- 网络断开、请求超时和重复点击。
- 登录失败或会话过期。
- 支付取消、支付结果未知、订单超时。
- 预约时段已被占用。
- 券码生成中、退款中、已退款、已核销和已过期。
- 客服/电话权限拒绝。

每个提交按钮点击后立即禁用并显示加载状态。创建订单、支付和退款均使用幂等键；失败时不可盲目生成新订单。

技术错误不能直接展示给顾客。顾客看到中文说明和客服入口；完整错误码、请求 ID 和时间写入服务端日志。

## 9. 隐私与安全

- AppSecret、商户私钥、APIv3 密钥只放服务器密钥配置。
- 小程序只保存短期顾客访问令牌，不保存支付密钥。
- 不在日志、埋点和报错中记录完整 OpenID、手机号、券码和身份证信息。
- 手机号、头像、昵称、位置只在真实需要时申请授权。
- 顾客拒绝位置权限后仍能购买，只是不显示距离和自动导航。
- 支付金额和收款商户由服务端重新计算。
- 券码接口必须校验订单属于当前顾客。
- 图片使用 HTTPS 对象存储/CDN 地址，并限制类型、大小和来源。

## 10. 前端开发排期

前提：平台级后端接口按约定提供并有 Mock 数据。

| 天数 | 工作内容 | 当日交付 |
| --- | --- | --- |
| 第 1 天 | 平台配置、入口解析、页面路由、设计变量、公共状态组件 | 能通过两个 `store_code` 打开两家测试店 |
| 第 2 天 | 门店首页、套餐卡片、套餐详情 | 顾客能看懂门店和购买规则 |
| 第 3 天 | 确认订单、微信登录、支付调起和支付结果 | Mock 支付闭环 |
| 第 4 天 | 订单列表/详情、预约、券码、我的 | 完整顾客闭环 |
| 第 5 天 | 异常状态、隐私、埋点、真机适配和回归 | 可提交体验版 |
| 第 6～7 天 | 接真实后端、低金额支付、问题修复 | 第一店测试版本 |

微信/腾讯审核和外部账号配置不包含在前端开发时间内。

## 11. 测试方案

### 功能测试

- 腾讯地图入口 A 打开门店 A，入口 B 打开门店 B。
- 修改入口参数不能读取别家非公开数据。
- 售罄/下架商品无法创建订单。
- 同一按钮连续点击只创建一笔订单。
- 支付取消可以继续支付；支付结果未知不会重复付款。
- 支付成功后正确进入预约或券码。
- 预约时段冲突能刷新并重新选择。
- 退款中券码不可使用。
- 已核销券不能再次核销。

### 真机测试

- iPhone 小屏、大屏。
- 常见 Android 微信版本。
- 弱网、断网、微信切后台和重新进入。
- 字体放大和长店名/长商品名。
- 腾讯地图、微信位置分享、小程序码和好友分享四种入口。

### 支付测试

- 0.01～1 元成功付款。
- 主动取消。
- 超时关单。
- 回调延迟和重复回调。
- 主动查单恢复状态。
- 全额退款和重复退款拦截。
- 核对顾客账单、商户平台和 SaaS 三方金额与商户号。

## 12. 第一店页面内容清单

缔丝风尚需要提供：

- 1 张门店头图，建议横图。
- 1 个店铺 Logo。
- 6 张以内门店环境图。
- 标准门店名称、地址、电话和营业时间。
- 30～80 字门店简介。
- 第一款套餐封面、名称、销售价和划线价。
- 套餐包含内容。
- 服务时长和预约提前时间。
- 长发、漂色、指定发型师等补差说明。
- 有效期、不可用日期和退款规则。
- 客服联系方式。

第一款商品建议数量固定为 1、库存 10 份以内，完成真实支付与退款验收后再扩大。

## 13. 上线验收标准

- [ ] 从腾讯地图入口直接打开正确门店。
- [ ] 首页首屏能看到门店、营业状态、地址和核心套餐。
- [ ] 三次主要点击内能够调起支付。
- [ ] 支付金额、商品和商户号由服务端确定。
- [ ] 支付结果以服务端确认为准。
- [ ] 支付、预约、券码、退款状态一致。
- [ ] 页面无技术编号、空白页和英文原始报错。
- [ ] 门店停业、商品下架、售罄和入口失效有清晰页面。
- [ ] 隐私、协议、客服和个人信息入口齐全。
- [ ] 两家测试租户共用一个 AppID 时无数据串店。
- [ ] 真机支付、退款和核销完整通过。
- [ ] 所有生产密钥均未进入小程序代码和 Git 仓库。

第一版达到以上标准即可提交试点，不应为了“看起来功能多”增加无验证价值的营销模块。
