# 微信位置＋商家独立小程序上线手册

这份手册用于把一家门店从“只有营业执照”推进到“微信位置页能进入商家小程序，顾客可付款、预约、出示券码，店员可核销”。

## 先说清楚：哪些能自己做

| 事项 | 我们系统能做 | 最终决定方 |
| --- | --- | --- |
| 类目预审 | 自动检查资料、有效期、主体、地区、地图点位并阻断缺项 | 我们可完成内部预审；官方开放范围仍以微信当期规则为准 |
| 官方报备 | 生成和跟踪工单、记录申请号、补件、结果凭证 | 微信官方或已核验的授权渠道审核 |
| 位置权限 | 配置 POI、小程序路径、授权流程和证据门禁 | 微信／腾讯位置能力审核后才可挂载 |
| 商品、支付、预约、核销 | 系统已完整实现 | 商户负责真实商品、履约和售后 |

结论：我们可以把申请前后全部体系化，但不能自己给账号“开官方权限”。后台故意不提供跳过审核按钮；没有官方编号和结果凭证，状态无法进入“已授权／已挂载”。如果官方页面显示“暂不支持入驻”或没有该类目，换接口、改店铺类型、伪造类目都不能解决，只能走官方咨询／授权渠道或等待开放。

## 一家试点店的完整顺序

### 1. 建门店和腾讯地图点位

1. 后台进入“门店管理”，创建真实门店，名称、地址必须与营业执照和门头一致。
2. 进入“微信连接”，建立“腾讯位置／服务 POI”连接。
3. 进入“服务 POI”，先搜索腾讯地图已有点位；有正确点位就绑定，没有才按真实资料创建。
4. 保存腾讯地图／微信审核通过的 POI 编号和截图。点位仍在审核时，不进入位置挂载。

### 2. 类目预审

1. 进入“准入与位置”→“准入工单”，选择“微信位置＋独立小程序”。
2. 类目填写真实经营内容，例如“美发”；不要借用餐饮或零售类目。
3. 逐项核验并保存凭证引用：当期类目开放、地区开放、营业执照、管理员本人、门头、店内、审核电话、腾讯地图点位、结算账户。
4. “规则来源”填写当日官方页面、客服工单号或授权渠道给出的受控材料。任一必需项缺失，系统显示预审失败并禁止报备。

### 3. 官方报备

1. 使用微信当前实际提供的入口，或与商家签约且可证明授权关系的渠道经理提交。
2. 提交后在后台填写官方申请号和提交截图／工单位置，状态变为“审核中”。
3. 收到补件时只补官方列出的缺项，保留原申请号；不要反复新建主体。
4. 收到结果后，由总部管理员核对官方页面，再填写“通过／补件／暂停／驳回”和结果凭证。
5. 普通店员无权把报备改成“通过”。这条权限用于防止业务人员口头报喜导致违规上线。

### 4. 商家自有小程序和支付

1. 商家用营业执照注册小程序，完成认证、隐私保护指引、服务类目和版本审核。
2. 商家在微信支付商户平台将该小程序 AppID 与商户号绑定；收款主体原则上与商家一致。
3. 后台“微信连接”新建“独立小程序交易与支付”。先选“模拟验收”，业务跑通后再建真实连接。
4. 真实连接只在后台输入：AppID、AppSecret、商户号、商户 API 证书序列号、商户 API 私钥 PEM、APIv3 密钥、微信支付公钥 PEM／公钥 ID、支付通知 HTTPS 地址。凭据不得发在微信聊天、文档或工单里。
5. 后台“准入与位置”→“商家小程序”登记小程序并选择该交易连接；上传商家授权凭证，核对商户号归属，确认回调已配置后才能启用。
6. 支付通知地址格式：`https://你的域名/api/v1/public/wechatpay/notify/后台小程序登记ID`。服务器必须使用公网 HTTPS，微信能直接访问，不能加登录页或 IP 白名单拦截微信支付回调。

微信支付服务端采用 API v3 JSAPI／小程序下单、RSA-SHA256 签名、微信支付响应与通知验签、APIv3 AES-GCM 解密；金额、AppID、商户号和订单号全部匹配后才把订单记为已支付。参考：[JSAPI/小程序下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791897)、[API v3 签名验签](https://pay.wechatpay.cn/doc/v3/merchant/4012365342)、[开发参数准备](https://pay.wechatpay.cn/doc/v3/merchant/4013070756)。

### 5. 微信位置服务挂载

1. 在微信允许的入口定义服务名称和小程序内部路径，例如 `pages/store/index`；禁止填外部网址。
2. 后台“服务挂载”选择：已通过报备的工单、同一门店、审核通过的服务 POI、已授权小程序。
3. 依次记录“服务已定义→等待授权→已授权→已挂载”。“已授权”和“已挂载”都必须填写官方编号与结果截图。
4. 系统再次检查：官方报备通过、服务 POI 存在、小程序已启用、位置服务已授权。缺一项都不能挂载。
5. 最终用普通顾客微信从腾讯地图／微信位置入口进入，核对门店名、地址、导航、服务入口和小程序页面。

微信位置底层依赖腾讯位置服务，腾讯官方能力介绍见：[腾讯位置服务](https://cloud.tencent.cn/solution/lbs)。实际“位置页展示服务”的入口和开放范围会随微信政策变化，以申请账号当日可见页面和官方客服结果为准。

### 6. 商品和交易验收

1. 后台进入“小程序交易”，创建商品草稿。销售价以“分”保存，前端以“元”输入显示。
2. 先用模拟连接完成：商品上架→顾客登录→下单→支付→预约→展示完整券码→店员核销→重复核销被拒绝→误核销撤销。
3. 切换真实连接后使用 0.01～1 元测试商品完成一笔真实支付；核对顾客支付记录、商户平台订单、后台订单三方金额和商户号。
4. 再测试支付取消、支付超时、回调重放、重复点支付、库存只剩一份时并发下单、券码二次核销、退款与投诉流程。
5. 试点通过后再增加第二家店，不能直接批量复制第一家店的 POI、主体凭证或商户号归属结论。

## 顾客小程序交付

仓库 `miniapp/` 是可导入微信开发者工具的顾客端骨架。复制 `config.example.js` 为 `config.js`，填写服务器 HTTPS API 地址和后台“小程序登记 ID”。AppSecret、商户私钥和 APIv3 密钥只能在服务器后台连接中配置，绝不能写进小程序。

正式发布前还要在小程序后台配置 request 合法域名、隐私保护指引、用户信息用途、服务类目和版本审核。域名必须完成微信要求的校验与合规手续。

## 试点通过标准

- 后台门禁显示全部通过，且官方编号能在官方页面反查。
- 微信位置页的门店、地址、导航、电话和小程序入口均正确。
- 顾客付款进入商家的商户号，不进入软件公司的代收账户。
- 支付回调验签成功；伪造、过期或金额不一致的通知被拒绝。
- 库存不会卖成负数；订单幂等；券码只能核销一次；误核销有审计记录。
- 联系电话、openid、券码、密钥均加密或脱敏，浏览器接口不返回连接密钥。
- 店员只拥有核销权限；只有总部管理员可记录官方审批成功。
