# POI Hub 零基础操作员完整 SOP

版本：V1.0（单店受控试点版）  
更新日期：2026-08-25  
系统地址：[https://poi.zzybyzz6369.my.id](https://poi.zzybyzz6369.my.id)  
适用对象：第一次接触微信小店、POI 和团购核销的操作员

## 0. 先读这一页

### 0.1 你在做什么

你要把一家真实门店按以下顺序接入：

1. 商家资料合格；
2. 商家本人开通微信小店；
3. 商家申请并通过本地生活相关资格；
4. 负责人完成微信真实授权；
5. 在 POI Hub 建立标准门店；
6. 搜索或创建腾讯地图点位，再提交微信服务门店审核；
7. 把标准门店与审核通过的服务 POI 绑定；
8. 创建一个试点团购商品并设置少量库存；
9. 完成真实购买、订单同步、核销、撤销/退款演练；
10. 通过上线验收后再正式宣传。

顺序不能跳。前一关没有“通过”，不要进入下一关。

### 0.2 三笔钱绝对不能混

| 钱的性质 | 谁收 | 操作员在哪看 |
|---|---|---|
| 顾客购买团购券的钱 | 微信小店按规则处理并结算给商家 | 微信小店后台；POI Hub 的“资金与对账”只做同步和核对 |
| 微信平台费用/佣金 | 微信按其规则收取 | 微信官方账单和 POI Hub 同步的微信账单 |
| POI Hub 服务费 | 商家按服务合同另行付给软件服务方 | 当前试点使用独立的合同、收款单和人工台账；不能记成微信佣金 |

### 0.3 看到这些内容立即停手

- 页面要求输入账号密码、短信验证码、支付密钥，但你不能确认页面来源。
- 商家主体、结算账户、营业执照、门店名称或地址对不上。
- 商家要求制作假资料、假地址或借用他人资质。
- 你不知道 AppID、类目 ID、品牌 ID、行政区划 ID、商品属性 JSON 或资质标识应该填什么。
- “操作中心”出现 `failed`、`permission_denied`、`token_invalid` 或类似永久错误。
- 顾客已经到店，但券的状态不明确。
- 商家要求从顾客货款中直接扣我们的服务费。

停手后截图“完整页面 + 时间 + 商户名 + 操作内容”，交给负责人。不要连续重复点击。

## 1. 人员分工

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 商家超级管理员 | 身份认证、结算账户、协议签署、微信授权、商品和价格最终确认 | 不能把账号密码和验证码交给代办人员 |
| 销售 | 介绍服务、确认需求、收普通资料、签约交接 | 不能承诺包过、保量或代收消费者货款 |
| 零基础操作员 | 按本 SOP 录入资料、提交已确认内容、查看状态、截图和升级异常 | 不能猜密钥、ID、资质、JSON；不能擅自退款、删商品、删 POI |
| 负责人/技术人员 | 建租户、配置真实连接、处理密钥和权限、判断接口错误、恢复服务 | 不能让敏感信息进入聊天、普通表格或公开工单 |
| 店员/核销员 | 按培训流程核验顾客券并核销 | 不能核销状态不明、门店不匹配或未真实履约的券 |
| 财务 | 核对微信结算和 POI Hub 服务费，保留收款凭证 | 不能把微信佣金当作 POI Hub 收入 |

本系统角色建议：

- `platform_admin`：平台负责人，权限最大。
- `tenant_admin`：商户管理员。
- `operator`：日常运营。
- `verifier`：只做订单和券码相关操作。
- `auditor`：只读核查。

遵循最小权限。普通操作员不要共用平台管理员账号。

## 2. 每家店建立一张“实施工单”

开始前为门店建立编号，例如 `LH-20260825-001`。普通资料放入受控文件夹，建议结构：

```text
LH-20260825-001_门店简称
├─ 01_合同与确认单
├─ 02_主体与门店资料
├─ 03_地图与POI
├─ 04_商品资料
├─ 05_审核截图
├─ 06_测试与验收
└─ 07_账单与收款凭证
```

文件名统一使用：`日期_内容_版本`，例如 `20260825_门头正面_v1.jpg`。

不要把密码、验证码、AppSecret、支付密钥、完整券码放进这些文件夹、聊天或表格。身份证和银行卡资料仅按公司批准的加密方式处理，并限制可见人员。

## 3. 阶段 A：销售交接验收

### A1. 收到以下基础信息

- [ ] 营业执照上的完整主体名称。
- [ ] 统一社会信用代码。
- [ ] 主体类型：企业或个体工商户。
- [ ] 门店全称。
- [ ] 省、市、区和完整街道门牌地址。
- [ ] 负责人姓名、手机号、邮箱。
- [ ] 对外联系电话。
- [ ] 营业时间。
- [ ] 经营类目。
- [ ] 门头正面照、店内环境照、能看清门牌和周边的定位照。
- [ ] 计划上线的服务项目、原价、售价、成本、服务时长和限制。
- [ ] 微信小店是否开通。
- [ ] 本地生活资格是否通过。
- [ ] 腾讯地图是否能搜到该门店。

### A2. 一致性检查

逐字比对营业执照、合同、结算账户、门店和微信后台。发现简称、错别字、地址缺少门牌号或主体不同，标红后让商家书面确认，不要自行修改成“看起来差不多”。

### A3. 阶段通过标准

只有以下三项同时满足才写“阶段 A 通过”：

- 普通资料完整、照片清楚；
- 主体和地址差异已有合理证明或书面说明；
- 商家确认不保证审核、流量、销量和收益。

## 4. 阶段 B：合同与 POI Hub 服务费

### B1. 确认服务项目

合同或确认单至少分开写：

- 一次性实施/开通服务；
- 系统服务期限；
- 是否包含代运营；
- 包含多少门店、商品和培训次数；
- 不包含哪些拍摄、投流、设计或上门服务；
- 资料不合格、审核驳回、商家不配合时如何处理；
- 服务终止、数据导出、退款和欠费规则。

### B2. 收费

当前版本没有完整的自动订阅与收费账本，试点只能使用公司批准的对公转账或独立服务费收款单，并由财务人工登记。

操作员必须保存：合同编号、账期、应收金额、实收金额、付款时间、收款凭证、开票状态、核对人。

禁止：

- 从顾客的微信小店订单中直接截取服务费；
- 把“资金与对账”页面里的微信佣金记成我们的服务费；
- 使用个人临时收款码但不给正式收据或台账；
- 用修改历史记录的方式处理减免或退款，必须新增调整记录。

### B3. 阶段通过标准

- [ ] 双方确认服务范围和费用。
- [ ] 首期款按约定到账或负责人书面允许后付。
- [ ] 财务台账和凭证完整。

## 5. 阶段 C：商家开通微信小店

本阶段必须由商家超级管理员本人操作，操作员只陪同和检查。

### C1. 准备

- 营业执照；
- 法人/经营者身份信息；
- 与主体匹配的结算账户；
- 实名微信号和超级管理员手机号、邮箱；
- 店铺名称、头像/logo；
- 页面要求的行业或品牌材料。

### C2. 进入官方入口

电脑优先：浏览器打开 [微信小店官方后台](https://channels.weixin.qq.com/shop)，由商家本人用微信扫码。  
手机常见入口：微信搜索“微信小店开店”，只进入带官方认证的结果。页面名称可能调整，以官方页面为准。

### C3. 按页面完成

1. 选择“申请开店”或“立即开店”。
2. 上传营业执照，核对识别出的主体名称、信用代码和经营者/法人信息。
3. 填写结算账户。企业对公账户名称、个体经营者账户名称必须按页面规则与主体匹配。
4. 设置超级管理员。该人员会接收重要通知并处理资金操作。
5. 商家本人完成身份/账户验证。
6. 商家本人阅读并签署开店及支付相关协议。
7. 填写店铺名称、头像和页面要求的品牌信息。
8. 提交后截图保存“审核中”页面和提交时间。

### C4. 审核结果

- 通过：保存店铺名称、店铺 ID/相关标识和通过截图。
- 补件：只按页面指出的缺项补充，不要全部重填。
- 驳回：完整记录驳回原文和时间，交负责人判断；禁止伪造材料重提。

### C5. 阶段通过标准

微信小店后台明确显示已开张/正常，结算账户可用，超级管理员能正常进入后台。

## 6. 阶段 D：申请微信本地生活能力

### D1. 申请前检查

- 微信小店已经正常开张；
- 经营类目与营业执照经营范围、门店实际服务一致；
- 页面要求的类目资质齐全；
- 退款、预约、服务限制和售后责任人已经确定。

### D2. 提交

由商家超级管理员进入微信小店后台，查找“本地生活”“类目管理”“资质中心”或当前页面对应入口，选择实际经营类目并按页面清单提交。页面名称和材料要求可能调整，必须以当天官方后台为准。

美发门店不要自行选择医疗、医美或其他不匹配类目。若页面要求公共场所卫生许可或其他行业材料，商家必须提供真实有效文件；不要猜“应该不需要”。

### D3. 阶段通过标准

- 后台明确显示本地生活相关类目/资格已通过；
- 能看到本地生活商品相关入口；
- 商家确认消费者付款和结算账户归属正确。

未通过前，禁止在 POI Hub 创建真实团购商品。

## 7. 阶段 E：登录 POI Hub 并确认商户空间

### E1. 登录

1. 打开 [https://poi.zzybyzz6369.my.id](https://poi.zzybyzz6369.my.id)。
2. 输入分配给你的个人账号和密码。
3. 不要使用他人的账号，不要让浏览器在公共电脑保存密码。
4. 登录后看左上/顶部“当前租户”，确认是本次操作的商家。

如果当前租户不对：点击顶部当前租户进行切换。仍找不到时停手，联系平台负责人。

### E2. 先看“运营总览”

重点查看：失败操作、待映射门店、待处理审核、低库存商品、对账差异、异常连接。

任何数字不是 0，不代表一定出错；但必须先点到对应页面确认原因。

### E3. 当前版本限制

“商户主控”目前只能停用/恢复已有商户，不能在页面创建新商户空间。新商户租户必须由平台负责人创建。零基础操作员不得自行调用接口或登录服务器创建。

## 8. 阶段 F：门店管理

页面：左侧菜单 → `门店管理`

### F1. 新建或核对门店

1. 点击“新建门店”；已有门店则点击“编辑”。
2. 门店编码：使用公司分配的唯一编码，例 `DSFS-LH-001`。不要随意改。
3. 门店名称：填写对外真实名称。
4. 详细地址：写到路、楼号和门牌号。
5. 城市、区县：与证照和腾讯地图一致。
6. 状态：正常试点选择“营业中”。
7. 点击“创建门店”或“保存门店”。

### F2. 复核

回到列表逐字检查编码、名称和地址。发现错误立即编辑。

不要随意点“归档”。归档会解除活动 POI 映射，必须由负责人批准。

### F3. 阶段通过标准

列表中只有一个本次试点的有效门店记录，名称和地址与资料一致，状态为“营业中”。

## 9. 阶段 G：配置真实微信连接（负责人/技术人员专属）

页面：左侧菜单 → `微信连接`

真实商用需要两个能力：

- `微信团购本地生活`：商品、订单、券、核销和账单；
- `服务 POI`：腾讯地图搜索、微信服务门店创建和同步。

### G1. 零基础操作员必须知道的限制

当前页面虽然能点击“新建连接”，但真实批量授权门户尚未完成，而且连接创建后页面没有安全的编辑/替换流程。行政区划 ID、第三方平台授权令牌等字段也没有完整的新手界面。

因此：

- 零基础操作员不得创建 `Live` 连接；
- 不得为了“先试试”创建 `Mock` 连接，真实商户一旦占用该能力会影响后续正确配置；
- 不得通过微信、邮件或表格索要 AppSecret、Access Token、回调 Token、EncodingAESKey、支付密钥；
- 由平台负责人通过受控流程完成两条真实连接并测试权限。

### G2. 负责人验收结果

操作员只检查并记录：

- [ ] 本地生活连接存在，模式为 `live`；
- [ ] 服务 POI 连接存在，模式为 `live`；
- [ ] AppID 已显示且属于本商户/正确授权方；
- [ ] 技术人员已用安全的只读/低风险请求验证连接可调用；当前版本的 `live` 连接状态和健康检查生命周期尚未完整实现，不能只看列表里的状态文字判断可用；
- [ ] 本地生活商品权限已验证；
- [ ] 券码核销权限或允许使用的核销组件已验证；
- [ ] 服务 POI 搜索所需行政区划 ID 已由技术人员配置；
- [ ] 回调验签和事件接收已测试。

任何一项未完成，阶段 G 不通过。

## 10. 阶段 H：搜索或创建腾讯地图点位

页面：左侧菜单 → `服务 POI` → `新建 POI`

### H1. 优先搜索已有点位

1. 选择“服务 POI 连接”。
2. “当前步骤”选择“已有腾讯地图点位，提交微信门店审核”。
3. 搜索词先填完整门店名；找不到再填“道路名 + 门店简称”。
4. 点击“搜索腾讯地图”。
5. 对照名称、地址和经纬度，只选择完全属于该门店的结果。

不要因为名字相似就选择。选错别人的点位会造成地址、审核和核销映射错误。

### H2. 地图上没有门店时

“当前步骤”选择“地图上没有门店，先创建腾讯地图点位”，按已审核资料填写：

- 名称、完整地址；
- 纬度、经度；
- 省、市、区/县；
- 腾讯地图行政区划 ID；
- 腾讯地图类目；
- 门店电话；
- 营业执照图片 URL；
- 门店简介；
- 门店图片 URL。

注意：当前页面要求图片 URL，不是本地上传。图片必须先由负责人放到批准的 HTTPS 素材存储，并提供可访问 URL。操作员不得使用临时网盘、个人相册外链或不明图床。

点击“提交腾讯地图点位审核”。提交成功后状态通常为 `map_pending`。等待地图点位审核并能被搜索到后，再回到 H1 选择已有点位。不能把地图审核单号当成最终微信 POI ID。

### H3. 阶段通过标准

能在系统搜索结果中找到唯一、真实、地址正确的腾讯地图点位，并得到腾讯地图 POI ID。

## 11. 阶段 I：提交微信服务门店审核

页面：`服务 POI` → `新建 POI`

1. 选择服务 POI 连接。
2. 选择“已有腾讯地图点位，提交微信门店审核”。
3. 搜索并选择阶段 H 已核验的地图点位。
4. 检查自动带入的名称、地址、经纬度。
5. 填门店图片 URL。
6. 填审核联系电话，确保有人接听。
7. 填营业时间，例 `09:00-21:00`，必须与真实营业一致。
8. “资质材料标识”、主体名称、证件编号只复制负责人提供的已验证值，不得猜填。
9. 点击“提交微信门店审核”。

提交后在“服务 POI”列表查看。常见状态：

- `under_review`：审核中，等待；
- `approved`：已通过；
- `rejected`：驳回，保存原文并升级；
- `deleted`：已删除，不可继续使用。

审核中不要重复创建。可按负责人安排点击“刷新审核”。审核通过后，选择页面上方的 POI 连接执行“同步”，直到列表出现最终微信 POI 信息。

### 阶段通过标准

服务 POI 状态为通过/可用，名称和地址正确，且不是 `audit:...` 或 `map:...` 形式的临时审核标识。

## 12. 阶段 J：绑定标准门店与服务 POI

页面：左侧菜单 → `POI 映射`

### J1. 候选确认

系统可能显示门店与 POI 的候选关系。逐项检查：

- 门店名一致；
- 地址一致；
- 距离合理；
- POI 状态有效。

全部正确才点“确认”。名称或地址不一致点“忽略”并升级，不要只看匹配百分比。

### J2. 手动绑定

没有候选时：

1. 点击“手动绑定”；
2. 选择正确的标准门店；
3. 选择正确的服务 POI；
4. 再次核对名称和地址；
5. 点击“确认绑定”。

“当前活动映射”应只出现正确的一对一关系。

不要随意“解除”。解绑后该门店不能用于当前券码核销。

### 阶段通过标准

标准门店和审核通过的服务 POI 已建立唯一活动映射。

## 13. 阶段 K：准备第一个团购商品

先在工单里完成商品确认，不要直接在后台临时编文案。

### K1. 必填商品卡

- 商家商品 ID：公司生成的唯一 ID，例如 `DSFS-LH-CASH-001`；
- 商品名称：3–60 个字符；
- 券类型：代金券、兑换券或次卡；
- 服务内容和数量；
- 售价、市场价、成本；
- 适用人群、适用门店；
- 是否预约、预约电话/方式；
- 可用时间和不可用日期；
- 有效期；
- 到店加价条件；
- 退款、过期和售后口径；
- 微信三级类目 ID；
- 微信品牌 ID；
- 券码来源；
- 商品头图 HTTPS URL；
- 微信商品属性 JSON；
- 商家 SKU ID 和 SKU 名称；
- 初始测试库存。

类目 ID、品牌 ID 和属性 JSON 必须由负责人根据微信当日规则生成并复核。零基础操作员只复制，不编辑结构。

### K2. 价格换算

POI Hub 价格单位是“分”，不是“元”：

| 顾客看到 | 后台填写 |
|---:|---:|
| ¥9.90 | 990 |
| ¥39.90 | 3990 |
| ¥99.00 | 9900 |
| ¥129.00 | 12900 |

提交前由第二个人复核一次售价和市场价。初次测试库存建议 1–3，测试通过后再调高。

## 14. 阶段 L：创建商品、查看审核和设置库存

页面：左侧菜单 → `团购商品` → `新建商品`

### L1. 录入

1. 选择正确的“本地生活连接”。
2. 复制已确认的商家商品 ID。
3. 复制已确认的商品名称。
4. 选择券类型。
5. 复制微信三级类目 ID和品牌 ID。
6. 券码来源按方案选择。无明确方案时使用负责人确认的默认值，不得自行改为商家预存。
7. 复制头图 URL和可用门店说明。
8. 完整复制已审核的微信商品属性 JSON。页面提示无效时不要删除括号或随便改字符，交负责人处理。
9. 复制商家 SKU ID、SKU 名称。
10. 以“分”为单位录入售价、市场价和测试库存。
11. 对照商品卡逐项朗读复核。
12. 点击“提交并等待微信处理”。

微信新增商品和库存是两个步骤。商品创建后，点击库存数字进入“调整库存”，再次把目标库存设为已批准的测试数。

### L2. 生命周期

- `under_review`：审核中，等待；
- `approved`：审核通过但不一定已上架；
- `listed`：已上架；
- `delisted`：已下架。

只有商家书面确认“可以上线”后，才在“生命周期”中点“上架”。

“删除”不可恢复，零基础操作员不得点击。需要暂停销售时优先“下架”。

### L3. 操作中心复核

页面：`操作中心`

商品提交、上架和库存调整后，查看对应操作：

- `pending`/`running`：等待，不重复提交；
- `retry_wait`：系统等待重试，截图并观察；
- `succeeded`：成功；
- `failed`：失败，记录错误并升级。

仅对明确可重试的失败使用“重试”。权限不足、参数错误、资质驳回、令牌无效不能靠连续重试解决。

### 阶段通过标准

商品内容、价格和适用门店正确；微信审核通过；测试库存正确；操作中心无未处理失败。

## 15. 阶段 M：真实测试订单与券码

上线宣传前必须完成一次闭环测试。测试也是真实交易，应使用符合平台规则的真实金额，不能制造虚假交易。

### M1. 测试准备

- 商家确认测试商品和库存；
- 顾客测试微信号不是操作员后台账号；
- 店员、运营和负责人同时在场或在线；
- 记录测试开始时间和微信订单号；
- 预先约定测试完成后的履约或合规退款方式。

### M2. 购买

测试顾客在微信内找到正确商品，核对门店、内容、价格和规则后正常付款。付款后截图订单状态，不要截图传播完整券码。

### M3. 同步订单

页面：`订单与券码` → `同步订单`

1. 选择正确的本地生活连接；
2. 输入微信订单号；
3. 点击“提交同步”；
4. 刷新订单列表；
5. 核对订单号、状态和金额。

如果券码没有出现，先看“操作中心”和“回调收件箱”，不要重复购买。

### M4. 核销

官方是否允许接口直接核销取决于商户实际权限；部分商户可能需要使用微信提供的核销组件。负责人必须先验证可用方式。

若 POI Hub 已确认具备直接核销权限：

1. 顾客现场出示自己的有效券；
2. 店员先核对商品、门店、人数/次数和状态；
3. 在“订单与券码”的券码列表找到对应 `available` 券；
4. 点击“核销”；
5. 选择正确门店；
6. 再口头确认“服务已提供或现在开始提供”；
7. 点击“确认核销”；
8. 刷新后状态应为 `consumed`；
9. 保存测试结果，不保存或传播完整券码。

不要在券状态不明、顾客不在场、门店不匹配或服务未发生时核销。

### M5. 撤销核销

只在误操作或经批准的测试回滚时执行：

1. 找到状态为 `consumed` 的券；
2. 点击“撤销核销”；
3. 核对券和原核销门店；
4. 得到负责人批准后确认；
5. 刷新，确认状态恢复。

微信对单券核销/撤销循环有次数限制。网络或系统错误时必须沿用原业务请求并查询状态，不要通过反复新建请求来“碰运气”。

### M6. 退款/售后

POI Hub 当前“同步售后”用于读取和记录微信售后，不是发起顾客退款的按钮。退款必须在微信小店允许的官方流程中由有权限人员发起或确认。

退款后，在 POI Hub：

1. 打开“同步售后”；
2. 输入本地订单 ID和微信售后单号；
3. 提交同步；
4. 核对售后类型、状态和金额。

### M7. 测试通过标准

- [ ] 下单金额正确；
- [ ] 订单能同步；
- [ ] 券状态正确且无明文泄漏；
- [ ] 指定核销方式成功；
- [ ] 撤销或退款路径至少演练一种；
- [ ] 操作中心没有未处理失败；
- [ ] 店员能独立复述核销前的四项检查；
- [ ] 商家签字或文字确认可以上线。

## 16. 阶段 N：正式上线

1. 保存商家“确认上线”的书面记录。
2. 将商品库存从测试数调整到批准数。
3. 确认商品状态为 `listed`。
4. 确认门店与 POI 活动映射存在。
5. 确认审核电话、预约电话和营业时间有效。
6. 给店员发一页式核销卡并现场抽测。
7. 记录上线时间、商品 ID、SKU ID、初始库存和负责人。
8. 上线后前 24 小时由运营重点观察订单、回调、核销和失败操作。

## 17. 日常操作清单

### 每天开店前

- [ ] 登录并确认当前租户。
- [ ] 看“运营总览”的失败操作和异常连接。
- [ ] 看“操作中心”是否有 `failed` 或长时间 `retry_wait`。
- [ ] 看“回调收件箱”是否有 `dead_letter` 或失败。
- [ ] 检查在售商品状态和库存。
- [ ] 确认当天预约、不可用时段和店员交接。

### 每次核销前

- [ ] 顾客本人在场并展示有效券。
- [ ] 商品内容和服务人数/次数正确。
- [ ] 券适用于当前门店和当前时间。
- [ ] 券状态是可用，且无退款/售后冲突。
- [ ] 顾客确认使用后再核销。

### 每天下班前

- [ ] 当日核销数与店员记录一致。
- [ ] 退款、撤销和异常订单有处理人。
- [ ] 失败操作已有工单或说明。
- [ ] 敏感截图已按规定处理，没有发到无关群聊。

### 每周

- [ ] 检查低库存商品。
- [ ] 检查待审核商品和 POI。
- [ ] 核对商家投诉、退款和核销错误。
- [ ] 抽查操作日志，确认没有共用账号和越权操作。

### 每月

- [ ] 在“资金与对账”按负责人提供的微信商品 ID 和日期同步官方账单。
- [ ] 只对有明确订单关联的差异进行核对。
- [ ] 未关联资金/券账单单独处理，不把两个总数硬相减。
- [ ] 财务在独立台账核销 POI Hub 服务费。
- [ ] 备份服务确认单、对账结果、收款和开票凭证。

## 18. 异常处理表

| 现象 | 操作员先做 | 禁止做 | 升级给谁 |
|---|---|---|---|
| 登录不了 | 核对网址和本人账号；截图错误时间 | 连续猜密码、共用别人账号 | 平台负责人 |
| 找不到商户 | 检查顶部当前租户 | 在错误租户继续录入 | 平台负责人 |
| 连接 `disconnected` / token 错误 | 截图连接和操作中心错误 | 重填密钥、把密钥发群里 | 技术人员 |
| `permission_denied` | 记录接口动作和完整错误 | 连续重试 | 微信权限负责人/技术人员 |
| 腾讯地图搜不到 | 换“完整地址 + 门店名”搜索一次 | 选择相似的别家门店 | POI 负责人 |
| POI 审核驳回 | 保存驳回原文、核对资料 | 伪造/重复提交 | 负责人 + 商家 |
| 商品审核驳回 | 保存原因、下架宣传素材 | 改类目碰运气 | 商品负责人 |
| 价格填错但未上架 | 暂停操作，联系负责人修正 | 为省事直接上架 | 商品负责人 |
| 价格填错且已上架 | 立即下架，记录影响订单 | 删除记录、隐瞒 | 负责人 + 财务/客服 |
| 顾客券显示不明 | 暂停核销，查微信订单和操作中心 | 重复点击核销 | 核销负责人 |
| 核销请求超时 | 查询券当前状态和原操作结果 | 用新请求重复核销 | 技术人员 |
| 顾客要求退款 | 按微信小店售后流程转有权限人员 | POI Hub 里随意改状态 | 商家售后负责人 |
| 对账有差异 | 核对关联订单、日期、退款/撤销 | 直接改金额使其相等 | 财务 |
| 回调 `dead_letter` | 截图事件类型、时间、错误 | 删除事件 | 技术人员 |
| 系统整体不可用 | 记录开始时间，暂停高风险操作 | 反复刷新并重复提交 | 技术人员/平台负责人 |

## 20. 离店/终止服务

1. 先下架商品，不要直接删除。
2. 处理未完成订单、可用券、售后和退款责任。
3. 完成微信账单和 POI Hub 服务费最终核对。
4. 取消不再需要的微信授权，由商家超级管理员确认。
5. 导出合同约定范围内的数据。
6. 平台负责人停用商户租户；数据按合同保留，不由操作员删除。
7. 保存终止确认、交接清单和财务凭证。

## 21. 当前版本的商业化前置升级

如果要把这套工作完整交给零基础人员并批量开户，以下功能必须先由产品/技术补齐：

1. 微信第三方平台授权门户，商家扫码授权，不再人工传密钥；
2. 商户空间的可视化创建、套餐选择和开通向导；
3. 连接健康检查、重新授权和安全替换流程；
4. POI 所需行政区划 ID、资质字段和图片上传的可视化选择；
5. 商品类目/品牌/属性模板，禁止新手手写 JSON；
6. 前台扫码核销或官方核销组件接入，并按商户权限自动选路径；
7. 服务费订阅、账单、支付、退款/冲正和发票台账；
8. 新手页面内的阶段门禁、双人复核、错误中文解释和一键生成工单。

在上述功能完成前，只能按本文实行“新手操作 + 负责人审核 + 技术配置”的受控试点，不能宣传全自动批量开通。
