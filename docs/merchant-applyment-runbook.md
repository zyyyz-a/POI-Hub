# 子商户可视化入驻：使用与上线交接

更新时间：2026-10-22。新版已部署到现有 SaaS 服务器，数据库版本为 `0022_merchant_applyments`。随后按用户明确要求，线上真实进件提交已开启，并已通过公网已登录接口确认生效；仍须资料完整、经营者授权和二次确认后手动提交。此操作没有提交任何商户申请，也没有开启门店收款。平台管理员可登录现有后台，从左侧「子商户入驻」开始办理。

本次发布与验证记录见 [2026-10-21 部署记录](deployment-release-20261021.md)。下文第四节保留作为后续维护人员的部署操作说明，不代表需要再次重复执行。

## 一、这次做了什么

后台新增「子商户入驻」入口（`/merchant-applyments`），平台管理员或商户管理员可使用。

支持范围固定为：个体工商户、营业执照经营者本人担任管理员、中国大陆居民身份证。不是给平台公司再申请一个普通商户号，也不把门店原来的普通商户号直接当作子商户号。

办理过程是：选择现有门店和平台真实支付连接 → 保存执照与经营者资料 → 补充门店照片及结算账户 → 核对并授权提交微信 → 查询微信审核进度 → 经营者本人进行官方确认/验证/签约 → 取得 `sub_mchid` → 关联门店的待启用支付档案。

保存草稿和上传照片只保存到本系统，不会向微信发送。只有服务端提交开关开启、资料完整、明确勾选授权并再次确认后，才调用微信真实进件接口。审核结果必须经过微信支付签名验证，不能由前端填写“通过”。

## 二、你上线后怎么点

1. 登录现有 SaaS，选择这家门店所属的商户空间。
2. 在「门店管理」确认门店已建好，名称和地址正确。
3. 进入「微信连接」，核对平台小程序交易/支付连接：真实模式、平台小程序 AppID、服务商商户号，以及签名私钥、商户证书序列号、微信支付公钥、公钥 ID。密钥不通过聊天或截图传递。
4. 进入「子商户入驻」，点「新建入驻申请」。选择刚才的门店和真实支付连接，点「创建草稿」。同一门店不能重复新建申请。
5. 第一步「执照信息」：照营业执照填写名称和注册号/统一社会信用代码，上传执照。执照有效期起止可一起留空；填写时必须准确。
6. 第二步「经营者信息」：填写执照经营者姓名、身份证号码、证件有效期、本人手机、联系邮箱，上传身份证两面。不要填平台工作人员的信息。
7. 第三步「门店与结算」：填写实际经营地址、行政区划编码、商户简称、客服电话、结算银行及账号，上传门头、店内照片、小程序服务页面截图。按实际行业要求补充特殊资质。
   - 所有门店使用统一平台小程序 AppID，不要求门店另做小程序。页面截图应显示平台内这家门店的商品/服务；小程序未完善或未上线时，按官方要求提供真实服务页面设计稿，不用报错页代替。
   - 门头和店内照片仍须来自实际经营门店，不能用平台公司或其他门店照片替代。
   - 银行账号可粘贴带空格的格式，输入及手动保存时自动去除空格，保留所有数字（包括前导零）；掩码、字母、短横线不会被猜测修补。旧草稿须由用户再次点击保存，系统不会后台擅改已有账号。
8. 核对官方结算规则和行业名称，勾选已核对；点「保存草稿」。可以分次保存，不必一次填完。
9. 第四步「核对提交」：先解决所有缺项，核对已保存的执照、门店、账号尾号、平台 AppID。变更过资料要重新保存。
10. 商户知情并授权后，勾选授权，再点「确认资料，提交微信审核」，阅读第二次确认弹窗。提交开关未开启时，该按钮保持不可用。
11. 点「查询微信进度」。如微信返回官方签约链接，由执照经营者本人扫码完成相应手续。没有链接时，以微信当前审核状态和官方通知为准。
12. 显示「入驻完成」并取得子商户号后，点「关联待启用支付档案」。系统不会自动打开收款。

## 三、哪些资料不能随便填

| 页面字段 | 填什么 | 不要填什么 |
| --- | --- | --- |
| 平台小程序 AppID | 当前平台小程序的真实 AppID | 未提供给本次申请使用的其他小程序 ID |
| 服务商商户号 | 平台服务商的商户号 | 门店原来的普通商户号 |
| 子商户号 | 微信确认进件完成后返回的 `sub_mchid` | 自己编的号码，或直接照抄门店原商户号 |
| 经营地址行政区划编码 | 实际经营地点对应的六位区县编码 | 腾讯地图 POI ID、邮政编码 |
| 微信结算规则编号 | 按当前官方结算规则对照表确认的 `settlement_id` | 凭印象填写的费率或行业编号 |
| 微信行业名称 | 门店实际业务对应的官方 `qualification_type` | 平台公司的“软件开发”类目 |
| 个人结算银行卡 | 执照经营者本人账户 | 平台公司或其他个人的账户 |
| 个体户对公账户 | 与执照主体匹配的对公账户 | 其他商户账户 |

本版不预置未经核验的行业费率、支行列表或区县编码，也不保证任意行业都能直接通过。服务端有基础格式检查，最终以微信的行业资质、产品权限和审核结果为准。

银行所在地编码 `bank_address_code` 在本次官方接口文档中为已废弃的选填字段，本版不要求填写；这与经营地址的行政区划编码不是一回事。

## 四、先上线页面，再开真实提交

供维护人员执行；以下是交接步骤，不代表已经操作了服务器。

1. 备份现有数据库、部署文件和配置，记录当前版本。保留原有支付回调地址、域名及密钥。
2. 部署本次后端和前端文件，安装现有锁定依赖；数据库执行 `alembic upgrade head`，目标版本为 `0022_merchant_applyments`，仅新增两张入驻资料表。
3. 服务端保持 `WECHAT_APPLYMENT_SUBMIT_ENABLED=false`。生产环境必须使用稳定、独立保存的加密密钥；丢失密钥将无法读取资料，不能随意更换。
4. 重启后端并更新前端静态文件，继续使用当前 SaaS 域名，不为此功能另换域名。浏览器强制刷新后应看到「子商户入驻」。
5. 先验证管理员能创建并读取草稿、普通运营人员无法读取资料、照片可更换/移除、资料格式错误不会回显敏感内容。不要把真实材料用于演示截图。
6. 核对服务商账户是否允许使用「特约商户进件」API。已经通过开发者身份、能调用查询接口、或已有微信支付公钥，均不能单独证明有真实提交权限。遇到 `NO_AUTH` 要核实官方权限，不要切换成普通商户收款来绕过。
7. 核对第一家商户的授权、主体、行业资质、结算规则及平台小程序展示情况，安排经营者本人配合办理。
8. 上述条件具备后，维护人员明确开启 `WECHAT_APPLYMENT_SUBMIT_ENABLED=true` 并重启后端。管理员刷新页面后再按第二节手动提交第一家真实申请。
9. 入驻完成只关联待启用支付档案；继续核对小程序 AppID 关联/授权、服务商与子商户对应关系、微信支付产品权限、APIv3 密钥、支付回调验签解密及订单幂等。之后再单独批准真实低金额支付、退款和到账验证。

支付进件不自动开通腾讯地图相关服务入口、POI挂载、视频号团购，也不代替小程序备案或代码审核。这些仍是各自独立的步骤。

## 五、异常时怎么处理

- **提交结果待确认**：可能已发给微信，暂时禁止再次提交。先查询同一个申请，系统保留原业务申请号；不要另建门店绕过。
- **微信暂未查到申请**：提交后至少等待五分钟，再由通过验签的官方“申请不存在”回复恢复可编辑；正在执行的提交会有更长保护时间。恢复后仍复用原业务申请号。
- **待修改补件**：按微信意见修改原申请，保存后重新明确确认。不是新开一个商户号。
- **签名或验签失败**：暂停，不采用未经验证的审核结果；核对商户证书、私钥、微信公钥 ID 和服务器时间。
- **申请单号或子商户号不一致**：系统拒绝覆盖原账户，联系维护人员按官方原申请核对。
- **已启用的收款账户与申请不同**：禁止自动替换。必须另走明确批准的账户变更流程。
- **进件接口权限不足**：资料继续保存在草稿中，不标记为已入驻；联系微信支付官方确认可用的特约商户进件路径。

## 六、资料保护与首版边界

- 草稿文字、照片及原始审核结果加密存储；照片不生成公开下载链接。列表不返回身份证、银行卡、姓名等填写资料。
- 详情仅管理员可读，浏览器不持久化到 localStorage；写操作校验登录、所属商户空间、CSRF 和资料版本。审计仅保留操作人、记录编号、状态及版本，不记录证件/照片原文。
- 支持 JPG、PNG、BMP 原照片，以及浏览器可解码的 WebP/AVIF，原图可达 20MB。先按真实字节识别格式，并验证图片可以解码，而不只看后缀或文件类型标签。误标格式、带尾部数据的JPEG等按需在本地转换为标准PNG/JPEG；小图优先保留原像素，超过微信5MB上限时自动压缩。原文件不变。HEIC/HEIF取决于浏览器解码能力，无法解码时须从手机导出JPEG/PNG；拒绝PDF、SVG、视频和损坏文件。后端不放宽格式检查。
- 页面显示最近一次上传照片的本地预览，提交前须放大核对文字清晰；上传错误同时显示在对应照片旁。所有转换在浏览器本地完成，不使用第三方服务。后端及反向代理保留5MB的处理后图片安全上限，单份申请最多20张照片。仍不支持企业主体或非大陆居民证件。
- 真实资料录入前，应落实用户告知、商户授权、内部访问管理和资料保存/删除制度。首版支持逐张移除本地照片，尚无自动到期清理和整单注销入口；移除本地照片不等于撤回已经发送给微信的资料，也不删除历史备份。
- 行业规则、银行/支行、行政区划尚未做成经过官方数据核验的联动选择器，需要管理员核实。不要用测试数据提交真实申请。
- 不承诺审核通过或固定审核天数。签约链接仅接收指定微信支付官方 HTTPS 域名。

## 七、验证记录

专项覆盖：草稿不外发、加密存储、媒体上传摘要及签名、敏感字段加密、缺项与授权拦截、跨商户权限隔离、版本冲突、网络超时保护、申请单身份绑定、子商户号变化拦截、原申请恢复、支付档案仅保存为待启用。

后端全部 198 项自动测试通过，前端全部 38 项自动测试通过，前后端类型检查、代码检查和前端生产构建通过；使用本机无界面浏览器检查电脑、核对提交和手机三种布局，只使用模拟数据，未发起真实业务接口请求。构建保留现有组件库大包的体积提示，不影响本次构建成功。

新增迁移已在独立 SQLite 测试库从空库升级并重复执行验证。全库 `alembic check` 仍提示旧 `direct_orders` 的四个外键差异；历史迁移 `0013` 添加了相关列和索引但没有建立这四个外键，不是本次新增表差异。本次不改动旧交易表，也未核查生产库是否已另行补齐。正式部署仍须先备份并在与生产一致的数据库环境演练。
